# CAUTIONS.md — Mini3D 注意事项

此处仅保存**跨模块、容易被忽略、可能导致错误修改的长期注意事项**。它不是任务流程、开发日志、测试清单，也不代替源码。具体操作请阅读 [OPERATIONS.md](OPERATIONS.md)，文件职责请阅读 [FILE_REGISTRY.md](FILE_REGISTRY.md)。

## 代码与文件

- **保护工作区**：修改前确认分支和未提交文件；不得擅自覆盖、清理用户资产、实验数据或本地构建成果。
- **尊重职责与共享契约**：不能因为任务属于 UI 就推断根因一定在 UI；先定位主要模块，再沿真实调用链调查必要的上下游。不要绕开统一的 Scene/Commands/Shot 状态，制造一套平行实现。
- **登记与源码同步**：新增、删除、合并、拆分、重命名生产脚本，或改变其职责、接口时，同次更新 FILE_REGISTRY；只登记现在存在的文件。内部实现变化但职责未变，无需添加历史叙述。

## Git 与交付

- **不为每一步自动提交**：修改文件、完成小步骤或调整文档，不意味着必须立刻 `git commit`。除非用户明确要求或任务已授权提交，否则可保留经过验证的工作区改动，由主 Agent 决定何时形成完整交付。
- **以完整、可验证的工作单元提交**：同一任务涉及的代码、必要测试与 Register 更新可以作为一次合理提交；互不相关的任务不要混在同一提交里。不要为了减少提交而失去可追溯性。
- **提交与推送分别授权**：`git commit` 不等于 `git push`，不因完成任务就自动推送、合并或修改 `main`。不覆盖用户既有提交和改动。

## 验证与资料

- **区分工作区绘制后端**：Arrange 与 Shot 共用场景渲染核心，但可分别配置。`MINI3D_RENDER_BACKEND=auto/native/python` 是共同设置，`MINI3D_ARRANGE_BACKEND` 和 `MINI3D_PHOTO_BACKEND` 分别覆盖对应工作区。显式 `native` 或 `MINI3D_REQUIRE_NATIVE_RENDER=1` 对相关工作区严格；旧 `MINI3D_REQUIRE_NATIVE_PHOTO=1` 只约束 Shot。
- **核对回退与渲染模式**：auto 缺 DLL 时直接选择 Python；尝试原生后出现资源不兼容时，日志及 `render_stats` 会记录原因。以实际后端为准，不能把 Python 帧算作 native 验收。原生支持 Unlit；Wireframe 会在 auto 下回退并在 `render_stats` 记录原因，严格 native 模式报错。
- **不要用表面通过代替实际正确**：CPU 单测不能代替 GPU 视觉验收；单张照片、某次短跑 FPS 和 P95 通过，也不意味着动态画面、完整编辑器及长尾性能都符合要求。
- **优先保护已有行为**：尤其是撤销/重做、场景存档兼容、摄影预览与 PNG 一致、真实深度、画质和用户操作语义。遇到跨模块变化，验证受影响的调用者。
- **历史资料不是当前事实**：需要实验依据或专项测试时，在 `docs/` 等已有资料中按相关关键词、条件和时间查找原始日志；找到后与当前代码核对。不要将旧日志改写成“现在已经解决”的保证，也不必给所有历史日志另建索引。
- **不为整洁而删除测试**：旧专项测试可能仍保护重要行为；测试脚本可由日志或测试搜索定位，不必逐个收入生产代码登记簿。删除/合并前确认当前覆盖与历史复现价值。

仅当形成新的、普遍适用的风险约束时才增补此文件；模块特有细节留在相应技术文档，具体命令留在操作规程，开发经过留在 Git 或日志。

- **SDL 窗口包装对象保活**：使用 Pygame 2.6.1 `Window.from_display_module()` 调整窗口时，必须保留返回的 Python 对象到 SDL 事件循环与窗口关闭之后。不要使用临时表达式或短命回调局部变量；SDL 的 `pg_window` 裸指针随后会被事件转换读取，可能导致随机原生内存崩溃。

- **异步加载与 GL 所有权**：后台只解析 CPU 模板/图像；活动 Scene、Commands、Undo 和所有 GL 调用留在主线程/context。结果经过主线程 adopt 和原命令提交，取消/退出屏蔽迟到结果。分帧 native 初始化的矩阵缓存必须记录 bundle 导出时的版本，不能在完成时记录新矩阵而漏掉期间的变换更新。
