# Pompeii 街区扩展

本地待验收，尚未提交。属于受庞贝启发的模块化街区，不是历史测绘复原。

## 打开与重建

```powershell
python -B -m mini3d --scene examples/pompeii/district.json
python -B tools/build_pompeii.py
```

原例子 `examples/roman_street/street.json` 保持不变。新地图从其相同 API 配方出发，23 栋建筑增至 85 栋（3.70 倍），85 个实例增至 435 个（5.12 倍）。包含七个命名区域：原街道出口广场、东侧市场、西侧住宅街、两条不同长度的巷道、后方横巷、柱廊庭院。屋宽、层高、退距、配色与建筑用途有变化，未复制整条街道排列。

布局由 `tools/build_pompeii.py` 使用现有 `spawn`、`create_group`、`transaction` API 搭建；坐标是有限的人工设计配方。保存结果是普通 v3 场景，每个建筑与地基独立可编辑，继续共享 AssetCache 的 39 个网格。它不是新的程序化城市系统；新增扩展在 API 会话里可一次撤销，加载存档按原规则清空撤销历史。

## 石砖恢复

摄影地面高度 0 与道路石块顶面 0 重叠，会盖住石块及砖缝。天空细节没有删除道路几何。新地图将背景地面降至 -0.14 米，低于道路砂浆底面 -0.12 米；建筑增加共享铺装地基。

`sky_preset('sunset')` 和 UI 的 Golden-hour 现在保留地面开关、高度、材质与缩放，和其他天空预设一致。显式 `sunset_preset()` / Photographic sunset 仍提供原摄影布景功能。旧存档若已开启高度 0 的摄影地面，可在 Lighting 关闭 Infinite textured ground，或把 Ground height 改为 -0.14。

## 性能改动与边界

- 保留本轮云层细节、太阳盘面与纹理状态复用优化，见 SPQR-PQ.md。
- 摄影地面阴影投影的包围盒角点使用 NumPy 批量计算，保持相同几何算法。
- 不透明物体在同材质内，仅重排互不接触的包围盒以复用 GPU 实例绘制。接触或重叠表面保留原先后顺序，避免共面材质变化；无效包围盒作为屏障。MASK、BLEND 和线框保留原行为。
- 排序按材质缓存并逐值检查，移动的摄影地面不会触发整个街区重新排序。每块最多 512 项，限制第一次准备的内存和计算量；释放 GPU 资源同时清理排序缓存。
- 扩大地图仍增加 CPU 工作量，不承诺达到小街道原有帧率。测试必须区分编辑器完整帧率和不含 UI/显示的渲染计时。没有降低照片抗锯齿或阴影质量来换取数字。

## 验收

```powershell
python -B -m unittest discover -s tests -p "test_*.py"
python -B tests/pompeii_smoke.py --output captures/pompeii-review
```

打开新地图，依次查看原街道、穿过拱门后的路口、东西街道、窄巷、庭院与俯视图。沿连通路线移动，检查石砖与屋顶；编辑一栋建筑，撤销并保存加载，再拍照。切换 Golden-hour、Stars、Moonlight，确认道路没有被背景地面覆盖。

单测覆盖三倍规模、共享网格、整批撤销/重做、存档往返、建筑独立编辑、主要步行路线通畅、屋顶不相交，以及排序依赖和缓存失效。GPU 脚本拍摄七个角度，对比合批开关下照片、检查保存加载一致性和 GL 错误，再连续移动计时。计时为 960×540、1x AA、2048 PCF 阴影，三轮各 20 帧；照片为 4x AA。

后续建议：用户确认地图后，优先针对扩大场景继续测量 CPU 阴影拟合与可见性准备；再考虑局部空间索引或缓存。暂不增加新街区、重型依赖、CSM 或 GI。
