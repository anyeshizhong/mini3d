日期：2026-10-11。以下保留测试时的原始记录。用户随后要求“请你改进”，已完成一轮定位、修复与回归；当前状态见[画面与性能改进](editor-quality-improvements.md)。阴影细节与高模场景持续导航的剩余限制也记录在该文档中。

## 第 1 项：点击 Camera View 后没有出现九宫格（暂不认定为 bug）

- 用户操作：在当前 mini3D 编辑器中点击 `Camera View`。
- 用户观察：没有出现摄影构图九宫格。
- 预期：进入 Camera View 后显示九宫格构图辅助线。
- 用户补充：需要先点击 `Create Camera`；此前现象不一定是 bug。
- 状态：暂不认定为 bug。后续如在已创建相机且九宫格开启时仍无法显示，再复现与定位；未修改代码。
- 已通过 IPC 连接用户当时正在操作的编辑器实例。
- 随后通过现有 IPC 读取到 `camera_view=false`、`shot_camera=null`。这是读取时的状态，尚不能断定点击无效或九宫格绘制异常的原因。
- 代码审查补充：已有九宫格绘制逻辑；当前实现要求先创建 Shot Camera 才能切换 Camera View。需后续确认用户点击时是否已有摄影机，以及界面错误提示是否充分。
- 已获取窗口截图：`captures/current-camera-grid-bug.png`，但该截图全黑，无法作为九宫格问题的视觉证据；不据此认定用户画面全黑。

## Bug 2：Editor View 与 Camera View 的画面差异严重

- 用户操作：观察并比较同一编辑器中的 `Editor View` 与 `Camera View`。
- 用户观察：两者画面明显不同，包括质感和摄影视角／成像效果。
- 问题重点：用户认为差异程度严重，不只是九宫格的显示问题。
- 状态：已记录，待复现与定位；本阶段不修改代码。
- 待后续核对：相机创建时机和之后的相机移动、镜头／视场角、画幅比例，以及两个视图的光照、材质和渲染设置。尚未确认根因，也不预先认定这些差异都属于预期行为。

## 补充问题：IPC 窗口截图全黑（已复现并修复）

- 现象：Scene 查询和操作正常，窗口 screenshot 返回成功但图像近乎全黑。
- 本机复现：旧实现读取默认窗口帧缓冲区；窗口最小化后截图近乎全黑。未断言用户当时一定最小化了窗口。
- 修复：在原主线程将完整 Editor 帧合成到自有 FBO，截图显式读取该帧；窗口显示使用同一帧。无第二个 Editor/Scene/GL context。
- 验证：真实 GPU/IPC 下正常窗口、最小化的三个工作区、窗口缩放、GL 状态恢复和 Shot Capture 后截图均通过；292 项单测及原 UI 回归通过。
- 同时移植 GitHub `feature/editor-ux-workspaces-20261011` 至 `e611a19` 的新 UI。
- 详细证据与范围：[截图修复和 UI 移植](editor-screenshot-fix.md)。截图修复当时未覆盖第 2、3 项，后续状态见文首改进记录。
