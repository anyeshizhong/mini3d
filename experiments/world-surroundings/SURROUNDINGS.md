# World Surroundings · 有限自由摄影机的城市外围

> 设计版本：v0.3 · 2026-10-20。状态：**SUR-00固定原型和首轮实测完成，C为继续开发主线；完整世界、画质与性能未通过。下一步SUR-01先处理地表分块/阴影参与/覆盖。** 真实结果与复现见 [SUR-00.md](SUR-00.md)，世界构建与性能分项验收。
> 当前任务与看板以 [PROJECT.md](../../PROJECT.md) 为准。本方案复用已有地形/SPQR 实验，不将旧实验改名为外围系统已完成。

## 目标与顺序判断

World Surroundings 是城市之外连续可信的地表、郊外与地理轮廓。摄影机在约定范围内走出街道、登上城墙、升高、横移和转向时，应感到城市位于一个完整世界中。天空与 Haze 是已有基础，外围系统还必须提供世界空间的地形、遮挡、视差和城市出口的延续。

**先做外围独立实验，不先完成整个 Spline 编辑器。** 连续地形和三维远景不依赖道路控制点、路基历史或道路 UI。首轮只用已有 Roman Street 和静态道路接续，建立城内→城门/出口→郊外的可见关系；必要时对示例走廊一次性贴地/整平，保存固定输入，不冒充可编辑道路或自动挖填系统。如果这条示例道路在摄影范围内悬空、穿地或断裂，必须局部修复后验收，不能以“道路后置”为由忽略。

当前优先顺序为 **SUR-00 确定视野与地理布局/简化对照 → SUR-01 建造连续世界 → SUR-02 建立可信郊外 → SUR-03 完整世界摄影验收与性能诊断 → SUR-PERF 后续性能专项**。近景材质Q后续、LAB-02C完整Spline、正式Terrain/Scene/UI/API集成延后，原需求与未通过项全部保留。外围原型通过不等于近景摄影画质或性能通过，也不自动授权集成。

## 摄影机范围与完整性契约

以下是首版**待验证目标**，不是当前已支持范围。SUR-00 首先测这个范围；失败必须记录位置、原因及修正，不得用更短路线或悄悄缩小范围冒充通过。

| 项目 | 首轮目标 |
| --- | --- |
| 世界原点/单位 | 固定城市锚点，Z-up；新示例1单位=1m，既有导入资产不隐式缩放 |
| 核心城市 | 约128×128m的固定罗马街区/出口示例，不承诺自动生成完整庞贝 |
| 有效摄影范围 | 相对城市锚点 X/Y 各为−200～+200m；摄影机在无遮挡可用地表上1.6～120m，不包括地下/建筑内部穿行 |
| 朝向与镜头 | yaw完整360°、俯仰−90°～+90°（含高空垂直向下），测试FOV 35°/52°/75°并补长焦机位；85mm对照须记录等效传感器尺寸与换算后的FOV，不直接把焦距当FOV；首版roll=0 |
| 可辨中远景 | 首轮以约0.25～2km的真实地形轮廓为候选尺度；更远支撑地表及far按完整视锥推导，不将2km直接当网格终点 |
| 越界行为 | 界外不承诺细节；独立窗口明确显示范围/越界状态，提供返回预设机位。不偷偷传送、缩放世界、跟随摄影机平移山体，也不修改正式相机控制器 |

区分三个概念：**核心可编辑区**使用现有真实模型；**有效摄影区**是本版承诺连续可信的相机位置集合；**视觉支撑区**比摄影区大，负责所有方向的背景。摄影区不能等于地形网格边缘，远山/田块/村落必须锚定世界位置。

“完整”至少满足以下标准：

- 街道、出口、中景与远景有连续地表；不存在悬浮地块、可见网格外沿、背面漏空、支撑面穿坡、断头贴图或平面转向跟随相机的山体。
- 在范围中心、四边、四角升降/旋转/向下看，地形连续、遮挡关系正确。只拍朝向山体的一侧或只用一条顺眼路线不算360°完整。
- 外围网格覆盖摄影区内视锥可能命中的地表；far裁剪不能扫过主山体/显眼地标。渲染范围、相机高度、FOV和far共同决定支撑范围，不能凭任意半径认定没有边缘。
- 地平线与天空接缝须单独观察。低/关闭Haze的诊断图检查几何；白天和夕阳图检查层次。Haze可以表现距离，不能代替缺失地表、掩盖接缝或挽救不合格的覆盖。
- 每个承诺区域保留原始PNG与连续移动证据。有限路线是可复现验收样本，还需范围内自由导航抽查；不宣称数学上证明所有姿态或无限飞行成立。

## 地理构图与示例范围

首轮只做一个**罗马郊外**示例。SUR-00就冻结城市所在缓坡/台地、主山脊、谷地开口和出城方向，SUR-01据此建地形，SUR-02再补土地分布与中景。接缝正确不等于画面可信：禁止仅用等距环形山墙或无方向的随机噪声围住城市。

地理构图先采用少量配置数据与确定性生成，不新增地理编辑器、侵蚀/水文模拟或完整道路系统：

| 控制信息 | 用途与约束 |
| --- | --- |
| 城市锚点、占地和台地高程 | 给现有罗马资产一个可信落点，城市地面与外围同源接续 |
| 主山脊控制点/高度、谷地走向/宽度 | 形成有辨识度的地标和开放方向；主次有别，不是四周相同的随机山峰 |
| 城门/出口锚点、静态道路走廊 | 道路沿谷地/缓坡进入郊外，有可见去向；只生成固定示例接续，不提供Spline编辑或通用自动挖填 |
| 田块、树林与农庄区域、固定种子 | 农田优先平缓地带，树林组织坡地/边界，农庄与道路/田块有关联；保留不规则与疏密，避免整齐重复摆满外围 |

所有控制信息共用世界坐标和同一地形描述，生成地表后再派生土地分布及固定物体落点，不能为构图叠一套与渲染/查询冲突的地形。首个示例可让主山脊位于城市一侧、谷地向另一侧展开，出城道路连接低地田块与少量农庄；以街道、屋顶、长焦与高空图判断关系和比例。

海岸城市、庞贝/维苏威留作后续配置验证，不同时开发三套场景，不在首轮引入真实海水或历史地理复原。城市锚点、外围范围、地理控制与种子应可重配并保留版本/摘要，避免做成一次性背景板；将低精度区域升级为可编辑Terra、迁移人工编辑并向外扩展的机制后置。

## 三层架构与首轮取舍

| 层次 | 表达与数据 | 第一版取舍 |
| --- | --- | --- |
| 近景城市 | 原Scene/共享Roman Assets、路面和真实阴影 | 所有A/B/C方案共用；固定布局与资产哈希，不开启完整地形编辑器 |
| 中景郊外 | 连续低成本地表、静态出城道路、田块、少量三维树形/农庄 | 首轮只放能验证尺度与视差的少量元素；SUR-02再补丰富度。使用原创几何或许可明确资产、固定种子/位置，不做用户植被刷或实时散布工具 |
| 远景地理 | 世界锚定低面数三维山地/山谷，平缓外缘接续支撑地表；现有天空与距离Haze | C为主要开发方向，A保留基线、B仅做最小对照；首轮不做真实海水、整套HLOD、clipmap、流送或物理大气移植 |

采用一份固定的高度/地理描述生成各静态分块。第一轮先用统一粗网格和一致边界验证闭合，再按固定空间分区给近/远地块不同密度；不同密度接缝必须共享边界顶点/高程并处理法线和T-junction。暂不按相机每帧改变网格，因此不把这种静态分区冒称为动态LOD。裙边只能补不可见裂缝，不能作为高空可见的垂直围墙。

支撑面优先使用同一地表的低频接续，避免中心Terrain与另一无限平面争抢深度。若需要复用解析地面，须先证明它仅覆盖无地形区域、不会穿出山谷、不会扩大近阴影；否则关闭Photographic Ground，使用普通连续网格。旧PlacementPlane、EditorGrid和Scene模型不变。

128×128m是拟建fixture的占地目标，不是现有Roman Street现成尺寸；现有单条直街最多12段加6段延伸，约72m，示例需另做固定布局。纹理按观看距离分配成本：城市附近可单独对照旧LAB-02B与Q候选，中远景优先单层/宏观色彩、预滤纹理和烘焙静态分布；保持同一光照和线性色彩，不用近景三层全采样覆盖千米地表。未来近景材质实验仍需独立通过；低成本外围不能被称为近景摄影级草地。

阴影策略先测现有原生路径，不假定已有独立远景pass。当前稳定近阴影视域约0.02～18m，但其深度拟合仍扫描普通caster；即使山体不在近处，其高度/斜光投影也可能拉大深度范围。现无逐实体castShadow字段，普通opaque/masked外围不能自动免除阴影成本。记录近/远矩阵、caster、draws、三角形和深度/耗时；若必须排除远景caster或隔离阴影视域，另做最小实验宏扩展，与同设置A比较并回归原有阴影，不修改生产ABI或悄悄关闭城市阴影。

## SUR-00：确定视野与技术路线

**A保留天空基线，B只做足以暴露视差/俯视局限的简化对照，C为主要开发方向。** 不把A/B/C各做成完整系统，不为二维替身开发专用编辑器、多角度烘焙管线或完整光照适配。完成相同输入下的必要对照、记录结论后进入C的连续世界建设；若C出现实质性错误则修正，不因预选C而跳过证据。

三组共用同一罗马场景、城市→郊外的地表接续、静态道路、标记物、太阳/曝光/天空、分辨率、AA、阴影、摄影机和路线。**A没有远山，不是取消共同地面。**

| 方案 | 只改变的外围表达 | 核心观察 |
| --- | --- | --- |
| A：仅天空背景 | 现有天空，无额外远山轮廓 | 原有世界空缺、地平线及基准成本 |
| B：二维远景 | 从C的同一地理轮廓在固定锚点烘焙的全景/远景层，保留来源和投影参数 | 平移视差不足、升高/俯视失效、接缝与额外成本；不因中心机位匹配就宣布可用 |
| C：低面数三维远景 | 同一山地描述生成真实世界坐标网格，进入正常深度/遮挡与光照 | 横移/升降视差、地平线、覆盖与阴影成本；不能只因“三维”而跳过验收 |

B应来自本项目生成的C烘焙或明确授权素材，不下载来源不明照片，不用生成示意图替代真实对比。烘焙不得重复叠加Haze或声称支持任意太阳变化；第一轮固定太阳，动态光照另列范围。白天与夕阳作为两个冻结光照批次时，B须按对应太阳重新烘焙、记录准备成本，不能把重新烘焙的截图当作实时昼夜变化通过。

固定机位至少包括街道约1.7m、出口/城墙约10～15m、高空约120m；每处有正向/回望/左右及俯视。连续路线包括出城、横移、升降、高空环绕、四边四角巡检，并检查边界内侧与界外状态。不强迫穿过建筑/山体，摄影机可见遮挡是正常结果。

镜头near/far先做小规模扫参，建议near .05/.1/.2m、far 2/4/8km为起始候选；根据最大摄影位置至主地标的距离选择统一参数，检查depth24下路面/地表闪烁、裁剪和阴影。记录fixture原始near与SPQR实际color near，避免自动调整掩盖精度风险。所有A/B/C共用最终镜头，不直接改生产Camera默认值；若单投影确实不足，再单列远景投影/深度方案，不在首轮默认引入reversed-Z或大坐标重构。

Haze起始候选为0、0.0001、0.0003（现有指数密度、按米制示例），不是物理标定参数。旧小场景的.002在千米尺度可能过度遮蔽，不能直接沿用后宣称完整。每一密度下各方案保持相同参数，不靠改变曝光/阴影让C显得更好。

验收分别记录**世界构建（功能/视觉）**和**性能**的通过、未通过或未测状态。SUR-03即使约20 FPS，只要可连续自由摄影、范围内世界可信且证据完整，也可记“世界构建原型通过、性能未达标”，继续进入SUR-PERF；不能据此把性能专项或正式产品记为完成。严重导航停顿、错误遮挡、内存失控、每帧重建/无意义上传、远山破坏城市阴影等架构问题仍须在发现阶段处理，不能全部推到最后。

性能以实际Intel UHD 620、1081×662、1x AA的同场景A复测为参照，保留远阴影1024/稳定近阴影4096的既有条件并记录实际启用状态；调参须全方案同步、另列对照。静止、平移、升降、环绕/高空与边缘巡检分别记录完整帧P50/P95/P99/最大值，至少预热24帧、采样120帧、3轮轮换顺序，所有慢帧保留。截图/录像与性能采样分开。

**33.33ms是SUR-PERF后续性能专项的目标底线，25ms是优先预算，不是SUR-00～03世界构建的硬性通过门槛。** 外围GPU颜色/阴影区段约3ms仅作初步设计参考；实际范围必须明确，不能把整帧与区段百分位相减当作精确增量。共同城市基线超预算时定位并列出共同成本，不以“外围增量小”宣布性能通过，也不因此反复推迟世界建设。保留全部真实样本，不沿用Q的17.49ms历史固定机位成绩。独立原型成绩不代表正式编辑器帧率。

报告同时记录几何/实体/材质数、draw calls、颜色/阴影三角形、纹理尺寸/估算载荷、CPU缓存、初次上传/启动、稳态上传/编译次数。静态外围在移动时不应每帧重建地形、重新编译Shader或重传全部纹理；此项需统计证明。外围颜色/阴影GPU区段计时是待补实验能力：旧baseline的render+glFinish不是GPU timestamp，Q的AO槽识别只测特定地形颜色，不能直接当成全部外围成本。未补齐时明确标记该项未测，不能用3ms设计参考代替实测，也不以开发完整计时系统作为世界建设前置。

## 技术调查与选择依据

“远山是真模型还是背景”没有统一答案。HLOD、图像替身和真实地形分别解决代理成本、屏幕占比与地表连续性；本方案选型依据是摄影机可到达的位置和观看角度。下表是2026-10-20查阅的原始论文/官方文档，不是已移植功能。

| 原始来源 | 已核实内容 | Mini3D决定 |
